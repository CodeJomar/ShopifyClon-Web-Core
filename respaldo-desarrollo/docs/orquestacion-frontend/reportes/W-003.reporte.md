## Bloqueo
`docker compose up -d --build api-core` levantó el contenedor, pero Spring no arrancó: al iniciar, Flyway/Hikari falla con `FATAL: (ENOTFOUND) tenant/user postgres.<ref> not found`. El error es de conexión al pooler de Supabase (el host del `.env` de la API no corresponde a la región o al proyecto del usuario). No toqué la base de datos ni el `.env` de la API. El contenedor se detuvo con `docker compose stop api-core`.

Para cerrar la tarea hace falta que el responsable confirme el `DB_HOST` correcto del pooler (sesión, IPv4) en `ShopifyClon-Api-Core/.env`. Además, para registrar y activar el usuario de prueba hace falta un correo al que llegue el código de activación, o que el envío de correo esté habilitado en la API (hoy el log indica "Correo omitido"). No pude crear el usuario por la API.

## Qué se hizo
- **Proxy** `src/app/api/[...ruta]/route.ts` (GET, POST, PUT, PATCH, DELETE, runtime Node). Reenvía a `API_INTERNAL_URL` + `/api/v1/<ruta>` con la query. Rechaza segmentos vacíos, `.`, `..` y los que contienen `/`, `\` o `%` (400). Copia solo `Content-Type`, `Accept`, `Idempotency-Key` y `X-Carrito-Token`. Agrega `Authorization` desde la cookie, `X-Tienda-Id` desde la cookie de tienda y `X-Correlacion-Id`. No reenvía `Set-Cookie` de la API. Timeout de 15 s; sin respuesta devuelve 502 con `codigo: WEB-001`.
- **Login**: en 200 guarda `datos.token` en la cookie httpOnly `otemu_sesion` (caduca con `expira_en`) y quita el token del cuerpo. Con exactamente una tienda fija `otemu_tienda`; con varias, la borra. Un 401 con sesión borra la cookie.
- **Rutas de sesión** `src/app/api/sesion/route.ts`: `DELETE` borra ambas cookies; `PUT { tienda_id }` valida UUID (400 `VAL-003` si no) y fija la tienda.
- **Cookies** `src/lib/sesion/cookies.ts`: httpOnly, SameSite=Lax, Path=/, Secure solo en producción.
- **Cliente** `src/lib/api/client.ts`: axios a `/api` (mismo origen). Se eliminaron la renovación por `/auth/refresh` y `sesion-reemplazada.ts`. `peticionApi<T>` devuelve `datos` y lanza `ErrorApi` (`src/lib/api/error-api.ts`). Un 401 fuera de `auth/*` lleva a `/login?siguiente=…`. `lib/connection` se mantiene.
- **Resultado** `src/lib/api/resultado.ts`: `{ ok, datos | error, estado, mensaje }` para los llamadores (auth y hooks genéricos).
- **Tipos** `src/dtos/core/respuesta-api.dto.ts`: `RespuestaApi<T>` y `Paginado<T>` en snake_case. Se borraron `baseResponse`, `checkStatus`, `oneQuery`, `dataQuery`, `createResponse` y `paginator`.
- **`next.config.ts`**: se retiró el rewrite `/api` y su TODO. `src/env.ts` se borró (ya no había consumidores).
- **Guard** `src/proxy.ts`: solo `/panel`, `/cuenta` y `/plataforma` exigen la cookie `otemu_sesion`; el resto es público.
- **Formato**: `formatearDinero(monto, moneda)` con `Intl` (es-PE) y `formatearFecha(isoUtc, zona = "America/Lima")`.
- **`.gitignore`**: se añadió `!.env.example` (la regla `.env*` lo ignoraba).

## Decisiones tomadas
1. **Cookie de tienda con varias tiendas**: si el login trae varias, se borra `otemu_tienda`; el usuario elige con `PUT /api/sesion`. Conservador.
2. **Sin `Secure` en desarrollo**: `Secure` solo en producción, según el texto de W-003 (`localhost` sigue funcionando).
3. **`X-Tienda-Id` se envía siempre que hay cookie**, no solo en rutas `/panel`. La API ignora la cabecera donde no aplica. TODO(Q-W-003) si la API la rechaza en rutas públicas.
4. **Fechas**: `formatearFecha` usa `Intl` en lugar de date-fns, porque date-fns no convierte zonas horarias sin dependencia extra.
5. **`auth` sigue usando endpoints que la API real no tiene** (`/auth/me`, `/auth/actividad`, `/auth/logout`, `/auth/recuperar`…). Se adaptaron solo para compilar, como pide W-003. W-004 los rehace.
6. **Lockout de login**: la API no devuelve intentos restantes ni `Retry-After`. `use-login` usa 60 s fijos. TODO(Q-W-003).
7. **`.env.example`** estaba ignorado por `.gitignore`; se añadió la excepción.
