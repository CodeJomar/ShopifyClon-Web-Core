## Comentarios para la integración y notas técnicas
1. **Locutor de accesibilidad de Next.js (`role="alert"`)**: En Next.js 16 se inyecta automáticamente en el cliente un contenedor oculto `<div role="alert" id="__next-route-announcer__"></div>`. Al validar alertas de error en la UI (como el error de autenticación `USR-004`), se debe filtrar por contenido (`page.getByRole("alert").filter({ hasText: /.../ })`) para no incurrir en violaciones de modo estricto de Playwright.
2. **Selector de campo contraseña**: En el formulario de login, el botón para alternar visibilidad de contraseña posee `aria-label="Mostrar contraseña"`. Para evitar que `getByLabel("Contraseña")` encuentre múltiples elementos, se utiliza `getByLabel("Contraseña", { exact: true })`.
3. **Manejo del recálculo de checkout (`CHK-004`)**: Al enviar la orden en el checkout, si la API detecta un recálculo en el total (`CHK-004`), el frontend muestra "El total cambió, por favor confirma nuevamente". El test contempla de forma resiliente la confirmación con `// TODO(W-016-C1)`.
4. **Botón de acción en `FormPanel` para registrar pago**: En `/panel/ordenes/[id]`, el botón para confirmar el modal de pago manual utiliza la etiqueta `"Guardar"` provista por el pie estándar de `FormPanel`.
5. **No se modificó código en `src/`**: Siguiendo la regla estricta de W-018, no se tocó ningún archivo en `src/` ni en `src/shared/components/**`.
