## Qué se hizo
- **Diseño de interfaz desacoplada**: Creada `AlmacenamientoImagenes` en `shopify.api.core.comun.almacenamiento` con método `subir(tiendaId, bytes, tipo) -> url`. Permite intercambiar proveedores (Supabase, S3/R2, disco local) sin modificar el servicio de negocio.
- **Implementación Supabase Storage**: `SupabaseStorageAlmacenamiento` con `@ConditionalOnProperty(name = "app.almacenamiento.proveedor", havingValue = "supabase", matchIfMissing = true)`. Utiliza `RestClient` de Spring Boot (sin dependencias adicionales).
- **Validación robusta de archivos**: `SubidaImagenServicio` valida `ContextoTienda`, exige permiso `Permiso.CATALOGO_GESTIONAR`, comprueba tamaño máximo (5 MB) y determina el tipo MIME mediante **magic bytes** (JPEG: `FF D8 FF`, PNG: `89 50 4E 47 0D 0A 1A 0A`, WebP: `RIFF....WEBP`).
- **Ruta segura y sin nombres de usuario**: La ruta en el bucket se genera con formato `{tiendaId}/{uuid}.{ext}` garantizando unicidad y aislamiento multi-tienda.
- **Controlador REST y Swagger**: `ArchivosPanelControlador` expone `POST /panel/archivos/imagenes` (`multipart/form-data`, campo `archivo`), protegido con `@RequierePermiso(Permiso.CATALOGO_GESTIONAR)` y documentado para OpenAPI/Swagger.
- **Configuración**: Actualizado `application.properties` con `app.supabase.secret-key=${SUPABASE_SECRET_KEY:}`, `app.supabase.bucket-imagenes=${SUPABASE_BUCKET_IMAGENES:ShopifyClon-Images-Core}`, `app.almacenamiento.proveedor=${ALMACENAMIENTO_PROVEEDOR:supabase}` y límites `spring.servlet.multipart.max-file-size=5MB` / `max-request-size=6MB`.
- **Excepción 503**: `AlmacenamientoNoConfiguradoException` con código `ALM-001` cuando falta `SUPABASE_SECRET_KEY` o `SUPABASE_URL`, permitiendo que la API arranque normalmente.
- **Constantes de ruta**: Añadida `Rutas.PANEL_ARCHIVOS_IMAGENES = "/panel/archivos/imagenes"`.

## Comprobación del bucket y cabeceras de Supabase Storage
1. **Comprobación del bucket**:
   - Bucket real verificado: `ShopifyClon-Images-Core`.
   - Propiedades confirmadas: `Public=True`, `FileSizeLimit=5242880` (5 MB), `AllowedMimeTypes=image/jpeg,image/png,image/webp`.
2. **Cabeceras aceptadas con clave nueva (`sb_secret_...`)**:
   - `apikey` únicamente: **ÉXITO** (200 / 201).
   - `Authorization: Bearer <clave>` únicamente: **FALLA** (HTTP 400 Solicitud incorrecta - el gateway de Supabase exige `apikey`).
   - `apikey` + `Authorization: Bearer <clave>`: **ÉXITO** (200 / 201).
   - Conclusión: `apikey` es la cabecera obligatoria. `SupabaseStorageAlmacenamiento` envía `apikey` y `Authorization` para máxima compatibilidad.

## Decisiones tomadas (no estaban en la tarea)
- Códigos de error asignados según convención transversal:
  - `ALM-001` (503 Service Unavailable): Almacenamiento no configurado (falta `SUPABASE_SECRET_KEY` o `SUPABASE_URL`).
  - `ALM-002` (422 Unprocessable Entity): Fallo de conexión o respuesta errónea del proveedor de almacenamiento.
  - `ALM-003` (422 Unprocessable Entity): Extensión o tipo MIME no mapeable a extensión conocida.
  - `ALM-004` (422 Unprocessable Entity): Archivo ausente o no es imagen válida (fallo en magic bytes JPEG/PNG/WebP).
  - `ALM-005` (422 Unprocessable Entity): Imagen excede los 5 MB permitidos.
- Doble validación de permisos: El controlador declara `@RequierePermiso(Permiso.CATALOGO_GESTIONAR)` y el servicio `SubidaImagenServicio` valida defensivamente `contexto.exigir(Permiso.CATALOGO_GESTIONAR)`.
- En caso de `almacenamiento.proveedor` no especificado, se activa `supabase` por defecto mediante `@ConditionalOnProperty(matchIfMissing = true)`.
